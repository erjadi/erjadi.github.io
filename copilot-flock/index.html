How it works & auth in plain English

Your own Azure relay. Device-bound Welcome Tickets. Hard privacy walls.

No third-party Copilot Flock server sits in the middle, and you never copy raw Azure keys to other computers or teammates.

1.

Runs in Your Azure Subscription (Just 2 Resources)

When you create a flock, Copilot deploys the relay into your own Azure subscription (rg-copilot-flock) using only Azure SignalR (Serverless) for live WebSockets and Azure Service Bus (Standard) for sleeping-PC offline queues—no third-party server or extra web app required.

2.

Device-Bound Join Code → Welcome Ticket

To add another computer or invite a teammate (@alice), the joining computer generates its own local Ed25519 + X25519 keys and outputs a signed Join Code; your Owner PC approves it and seals a Welcome Ticket encrypted specifically to that device's X25519 public key.

3.

Stateless Per-Message Encryption & Signatures

Every message derives a one-time AES-256-GCM key from a fresh 256-bit random salt via HKDF-SHA256, carries the sender's owner-signed MemberCert, and is signed by the sender's Ed25519 device key.

4.

Your Computers vs. Collaborators

Your own enrolled computers (personal and work) can discover and coordinate across all of your local sessions via the Copilot Flock Coordinator and Thread Tracker, whereas invited teammates and guests see zero existing sessions by default.

5.

Share Only What You Choose — and Leave Without a Trace

A collaborator can only see or message a conversation when you explicitly tell Copilot "Share this thread", and any machine can run a verified traceless unenroll (flock.mjs uninstall) that confirms leave receipts before removing local Flock files, startup tasks, and MCP entries.

Before you install

Three honest answers to common questions

What a developer wants to know before running setup on their machines.

Can another Copilot read my private work or run commands on my computer?

Between your own computers

Your own enrolled machines are trusted peers so you can ask one computer to help another seamlessly.

With teammates and guests

External flocks default to opt-in thread sharing only. Collaborators cannot list your unshared sessions or read unshared transcripts. When a message is delivered to a shared session, it runs under that session's Copilot permissions—so keep guest-shared sessions in interactive "Ask before running tools" mode and only invite people you trust.

What does this cost in Azure, what does it install locally, and how do I remove it?

In Azure (rg-copilot-flock)

  • Azure SignalR Serverless: Free_F1 ($0/mo, 20 concurrent connections & 20,000 messages/day—plenty for 2–4 computers) or Standard_S1 for larger always-on fleets.
  • Azure Service Bus Standard: Required for durable per-machine offline topics and subscriptions with FlockSendRule & FlockListenRule (billed by Azure on the Standard tier, typically ~$10/mo base depending on region).

Only two resources by default for new setups: No App Service broker is needed. Existing legacy v3 installs stay on their legacy backend unless explicitly migrated (--legacy-broker remains supported).

On your computer

Installs ~/.copilot/flock/, registers a login background service (Task Scheduler on Windows, systemd/launchd on Linux/macOS), and registers the copilot-flock MCP server.

Traceless Unenroll & Clean Removal

node ~/.copilot/flock/flock.mjs uninstall sends signed leave requests to your flocks and retains recovery state if any leave is still pending. It verifies daemon creation identity and installation.json SHA-256 script ownership before removing proven Flock-owned files, tasks, skills, and MCP entries. It never touches your Copilot conversations (session-state, chats, data.db), modified files, or git repos. Delete the dedicated Azure resource group only when you no longer need it (az group delete --name rg-copilot-flock).

What happens when my laptop is closed, or I'm behind NAT / Wi-Fi?

Outbound connections only

Every computer connects outbound over HTTPS/WebSockets—no inbound port forwarding or static IPs required (subject to your network's normal outbound firewall/proxy rules).

Sleeping computers don't miss messages

While a computer is offline, messages wait in Azure Service Bus and deliver automatically once it wakes up and reconnects.
